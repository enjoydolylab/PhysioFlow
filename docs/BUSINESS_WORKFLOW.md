# 业务流程与能力边界

更新：2026-09-06。范围：v0.6.0-beta.4。本文描述当前业务；尚未实现的界面改版在[路线图](refactor/OPTIMIZATION_PLAN.md)中列出。

## 产品定位与角色

PhysioFlow 帮助研究人员把实验定义转换为参与者画面、运行事件与可分析的数据包。实验设计者负责流程、刺激和问卷；操作员负责运行前检查、采集和故障处理；分析人员负责核对会话、事件、响应与排除标准。三种角色可以由同一人承担，桌面应用没有因此建立独立账户权限。

Hosted 服务另有 owner/editor/operator/analyst/viewer 的认证权限，这是部署能力，不能套用到本地桌面角色。

## 业务对象

| 对象 | 业务意义 | 关键边界 |
| --- | --- | --- |
| Project | 组织同一研究的协议及版本 | 不是一次采集 |
| Protocol / Version | 定义实验流程、参数、资源及组件配置 | 草稿可修改；冻结版本用于固定运行配置 |
| Graph Node / Edge | 表达新协议的操作、控制顺序和值依赖 | 画布位置不决定执行顺序 |
| Group / Subflow | 组织或复用节点片段 | 不能自动获得旧 Block 的试次重复、随机化语义 |
| Asset / Stimulus pool | 资源文件及可共享的刺激集合 | 资源引用不等于二进制文件已存在 |
| Questionnaire | 题目、选项、条件、评分和提交规则 | 专用表单运行器，不能假设全部由通用 UI 树编辑 |
| Participant UI | 某个节点的参与者画面 | 不是整个 Protocol 的控制图 |
| Session | 一次运行与参与者上下文 | 一个协议版本可以产生多个会话 |
| Event / Response / Snapshot | 事实日志、响应及恢复状态 | 检查点不是全部未完成输入的备份 |

## 两条实验设计路径

### 新协议：Composer V2

从空白或 Emotion / Stroop / Go-No-Go 模板创建 Protocol Graph。控制边决定先后、条件和循环；数据边及绑定传递变量和输出。Quick、Design、Advanced 和 Protocol JSON 编辑同一份 Graph。

`experiment.cognitive-task` 内部组织 Stroop / Go-No-Go 试次；普通 Graph 节点组合还没有统一的通用 Trial 容器。画布分组、子流程、逻辑循环、随机分支、刺激池是不同能力，不能混用术语。

### 旧协议：Block → Trial → Step / Flow

旧协议仍有独立编辑、运行与导出路径：

- Blocks 按保存顺序执行；每个 Block 的 order rule 排列其内部 Trials。
- Block Repeat 重复一个区块；Trial Repeat 连续执行同一 Trial。
- 固定、随机、手动及循环 Latin square 可用于 Trial 顺序。Latin square 行由会话设置选择，不自动分配参与者配额，也不等于所有平衡设计。
- 随机条件约束按 Trial.condition 判断，作用于每一轮 Block 内；不保证跨 Block 边界。beta.4 对不可满足的约束报错，约束模式要求 Trial Repeat = 1，可复制 Trial 后参与排序。
- 迁移创建新 Graph 草稿并保留来源；重复、随机及复杂分支必须审阅迁移报告。不能把迁移成功等同于实验等价。

具体步骤见[迁移指南](refactor/MIGRATION_GUIDE.md)。

## 从设计到数据

| 阶段 | 研究者要完成的事 | 应得到的结果 |
| --- | --- | --- |
| 设计 | 选择模型、定义条件、次数、分支和退出条件 | 可解释的执行流程 |
| 配置 | 选择刺激、问卷、结束方式和所需设备 | 参数与资源完整 |
| 预览 | 检查画面，再试运行计时、响应和异常操作 | 可复现的试运行记录 |
| 冻结 | 修复阻塞错误，审阅迁移事项，冻结版本 | 有版本和配置哈希的实验定义 |
| 采集 | 设置参与者编号、检查存储和设备，开始会话 | 事件、响应、状态和设备记录 |
| 复核 | 检查失败、重试、跳过、缺失及导出清单 | 与该协议版本对应的数据包 |

画面预览不执行完整实验；试运行也不能代替真实硬件时间精度测试。完成界面与保存成功是两个状态，保存失败时先重试或导出。

## “随机化”分别指什么

| 功能 | 改变的对象 | 不保证什么 |
| --- | --- | --- |
| 旧 Block order rule | Block 内 Trial 顺序 | 跨被试配额或跨 Block 条件约束 |
| Graph 随机分支 | 本次选择的控制出口 | 遍历全部分支或试次数量平衡 |
| Graph 共享刺激池 | 节点本次使用的刺激 | 参与者条件分组或完整流程重排 |
| 问卷随机顺序 | 问题或选项排列，视配置而定 | 实验节点顺序 |
| 认知任务生成器 | 专用任务的内部试次列表 | 任意实验的全因素设计 |

新 Graph 会话的共享池按完成或 Skip 消费，Retry 保留当前刺激；池耗尽后重复同一种子顺序。旧恢复快照可保留 legacy-stride 规则。设置页顺序预览只是名义首轮，不预测分支和循环。

## 自定义的边界

文本、媒体、输入、按钮及布局可以通过 Participant UI 编辑器配置；固定像素宽高在运行端生效。自由布局保留像素坐标，越界时可滚动，不会自动缩放刺激。使用目标窗口尺寸核对，尤其是呈现大小有研究含义的任务。

Questionnaire、Wait 和其他运行时生成结构的节点应通过专用参数编辑；不要假设所有节点都接受任意 UI 替换。Custom HTML 为禁用脚本的 sandbox iframe；Protocol JSON 和声明式 SDK 不支持注入任意 JavaScript。可信 Control Handler 和设备 adapter 是开发者集成接口。

## 数据交接与边界

Graph 完整导出包含原始事件、响应、协议与运行快照、组件/资源清单、数据字典及质量报告，详见[数据契约](refactor/DATA_CONTRACT_V2.md)。旧运行器另有完整和简化导出；两条路径均有 BIDS 风格导出实现。不得用固定文件数或列数解释全部包，也不宣称未运行验证器的 BIDS 合规性。

当前检查点不能完整恢复未提交问卷与认知任务内部进度；多个会话文件不是整体事务。物理设备同步、长时间录制和研究人员独立操作仍需验收。高级 Hosted、变更集和 SDK 不属于首次本地实验的必经步骤。
