# PhysioFlow 研究試用の確認手順

この文書は試用の手順です。実施結果はまだありません。自動試験で使った映像と信号は確認用の素材・合成信号です。

## 準備

研究者、実験員、参加者の立場でそれぞれ確認します。同じ人が兼任した場合は記録してください。ブラウザの種類・バージョン、実施日、アプリのバージョンとソース状態を記録します。

実際の映像ファイルと計測機器がない場合は「確認用素材・合成信号」と明記します。PhysioDB 連携には PF のサーバが必要です。静的 Web 試用パッケージだけでは DB サーバ機能は動きません。実験員のアクセスキーと DB のトークンは参加者へ渡さず、記録表にも書きません。

## 研究者による確認

1. 「説明 → 刺激 → 1～7 の評価 → 終了」の短い実験を作成します。
2. 説明文、刺激、必須回答を編集し、保存します。再度開いて同じ内容になっているか確認します。
3. 不足している刺激を設定した状態で実行を試み、問題の場所と修正方法が分かるか確認します。
4. 設計を確定して実行します。設計の ID とバージョン、実行の ID を記録します。
5. 完了した実行を開き、回答と観察メモ、エクスポートを確認します。

## 実験員による確認

1. 参加者コード、刺激、信号と原記録の開始状態を確認します。
2. 実行中に一時停止し、参加者画面の停止を確認して再開します。
3. 理由を記入して再試行またはスキップします。観察メモを追加し、記録への反映を確認します。
4. 完了後に PhysioDB の Research、Experiment、参加者コードを選び、イベントと回答を送信します。
5. 原記録がある場合、samples.jsonl とチャンネル対応を指定して追加します。途中で停止し、同じファイル・記録名・対応で再開します。
6. 読み戻し確認後、同じ参加者の別の実行と区別できるか確認します。ブラウザを開き直し、実行で絞り込み、タイムライン、回答、原信号を確認します。

## 参加者による確認

1. 初めて見る説明だけで開始できるか確認します。
2. 刺激と回答画面を操作します。未回答時の案内、送信後の反応を確認します。
3. 一時停止中に何をすればよいか分かるか、再開後に回答が混ざらないか確認します。
4. 終了したことが明確に分かるか確認します。

## 観察記録

結果を実施後に記入してください。空欄を成功と解釈しません。個人名ではなく管理用コードを使います。

| 確認者コード | 役割 | 手順 | 自力で完了 | 要した時間 | 必要だった説明 | 困った場所 | 期待した動作 | 実際の動作 | 実行ID・添付記録 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | |

不具合には再現手順、重大度、担当、修正・再確認結果を追加します。保存失敗、回答の欠落・混在、原信号の不一致は優先して確認します。

これは少人数の試用用です。正式な効率・可用性評価を行う場合は `docs/refactor/USABILITY_STUDY_PROTOCOL.md` の人数、課題、指標、署名と JSON テンプレートを使用してください。少人数の試用だけで正式な可用性評価が完了したとは扱いません。
