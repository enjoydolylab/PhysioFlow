# PhysioFlow beta.20：実験中の操作と研究データの出力

## 実験中に操作の確認が届かない場合

一時停止・再開・再試行・スキップ・観察メモを送信すると、実験側の確認を待ちます。確認が届かなくても、操作が実行済みの場合があります。

1. 「操作結果を確認」を押します。元の操作を再実行せず、記録された結果を照会します。
2. 実行済みの確認が届くと待機が解除されます。メモなどの成功が確認された場合、入力欄は空になります。
3. 確認記録がない場合は、実験ウィンドウで現在のステップ・停止状態・観察メモを確認します。
4. 確認後に「実験側を確認済み・待機を解除」を押します。このボタンは待機を解除するだけで、実験を再開したり元の操作を再送したりしません。

「Disconnected」の間は操作結果を照会できません。実験ウィンドウを確認してください。結果の照会に使う記録は現在の実験ウィンドウ内にあります。実験ウィンドウの再読み込み後は、過去の確認を取得できない場合があります。

## 保存した実行のデータを出力する

1. PF サーバの管理画面へ接続し、DB の Research、Experiment、参加者を選びます。
2. 実行で絞り込み、設計名・バージョン・設計の識別ハッシュを確認します。
3. 「この実行をエクスポート」を押し、ブラウザのダウンロード一覧で ZIP を確認します。
4. 再取得が必要な場合は画面の「データパッケージを再ダウンロード」を使います。表示が消えた場合は再度エクスポートします。

検索・回答のみ表示・ページ表示で絞り込んでも、その実行の保存済みイベントと回答をすべて出力します。出力前に DB の最新記録を読み直します。保存されていない記録を補う機能ではありません。設計の不一致などでエラーになった場合は、エラーを解消してから出力してください。

| ファイル | 内容 |
| --- | --- |
| events.jsonl | DB に保存された実行イベントの完全な記録 |
| events.csv | イベント一覧。データ全体は data_json に含む |
| responses.json | 元の回答記録。置き換えられた回答や問診のメタ記録も含む |
| responses.csv | 回答、質問名、元の記録。空値・配列・ゼロ・負値も保持 |
| protocol.json | その実行で保存した設計 |
| manifest.json | 取得時刻、件数、設計と保存先の識別情報、各ファイルの検証値 |

CSV は UTF-8 BOM 付きです。回答が数式として実行されるのを防ぐため、数式のような文字列には先頭にアポストロフィを付けます。文字列の厳密な原記録を使う場合は responses.json を参照してください。manifest の lastVerification は過去の同期確認です。今回すべての原信号を再検証した結果ではありません。

原信号のサンプルはこの ZIP に含まれません。信号の出力機能から別途取得してください。別の実行を選んだ場合は別のパッケージになります。

## 検証の範囲

beta.20 は合成信号と確認用素材で検証済みです。正式な機器、原映像と原時間の実験、実際の研究者・実験員・参加者による試用結果はまだありません。

## ステップが変わった後の操作

操作を送った後でステップまたは再試行の回数が変わった場合、その操作は拒否されます。現在のステップを確認してから必要な操作を行ってください。以前のステップへの操作を新しいステップに適用しません。

## 保存異常の確認

実験終了後の保存状態は、途中のチェックポイントとは別に確認します。最終保存が失敗した場合は監視画面にエラーが表示されます。実験ウィンドウを開いたまま、そこで保存を再試行してください。サーバ保存は別に表示されます。ローカル保存済みでもサーバ同期が成功しているとは限りません。
# beta.20 操作上の補足

初回の「実験待ち」はまだ状態が届いていないことを示します。切断の案内が出た場合、表示値は最後に受信した状態です。同じブラウザーで実験ウィンドウを開いたままにしてください。更新が再開すると操作できます。

再試行・スキップ・観察記録には理由またはメモを入力してください。確認が届かない場合は操作結果を確認し、実験画面を確認してから待機を解除してください。

素材の事前確認に失敗した場合、必要な原ファイルを復元して「素材を再確認」を選びます。違う内容のファイルは検証で拒否されます。参照を変更する場合は実験手順に戻ってください。
