# 产品与工程优化路线图

更新：2026-09-06。基线：[beta.4 当前状态](IMPLEMENTATION_STATUS.md)。本页只列后续计划，已完成修复见发布说明与验收报告。

## 业务主线

设计协议 → 配置刺激与问卷 → 预览检查 → 冻结版本 → 开始采集 → 复核导出。

这条链路尚未变成统一的阶段式导航。下一轮以“基线 → 随机刺激 → SAM → 休息”为样板，贯通创建、保存重开、试运行及数据核对。

## 优先工作与验收

| 优先级 | 工作 | 产出 / 验收方式 |
| --- | --- | --- |
| P0 | Windows 安装包实测 | 干净账户、实际 WebView2、常见缩放下完成保存、重开、运行、导出 |
| P0 | 真实设备与同步 | 并发连接、权限取消、断连恢复、目标时长录制；有计时需求时用硬件测量 |
| P0 | 研究人员可用性 | 两类研究人员完成规定任务、记录操作和提示、缺陷闭环及三方签收 |
| P1 | 主流程与信息架构 | 当前阶段、下一步、草稿/冻结/保存/失败状态可理解 |
| P1 | 节点编辑一致性 | 内容、结束条件、记录与高级设置一致分层；错误定位到字段或连接 |
| P1 | Participant UI | 自动布局默认、模板入口、目标尺寸和自由布局行为清晰；画面预览与试运行区分 |
| P1 | 视觉系统 | 字号、间距、按钮、选中态、对比度和主题统一；研究者风格不改变参与者刺激参数 |
| P1 | 模型边界 | 先明确 Graph Group/Subflow 与旧 Block 的差异，再设计通用 Trial，避免隐式改变旧实验 |
| P1 | 稳定性与维护 | 未提交内部状态恢复、多文件保存一致性评估、大模块拆分与 schema 重复收敛 |
| P2 | 发布工程 | 签名、tag 自动构建、Windows CI 矩阵、离线 WebView2 与其他平台包 |
| P2 | 可选部署 | 自托管操作体验、备份演练；自动更新须在部署策略明确后再引入 |

P0 是正式采集和稳定版判断所需的证据，不代表 beta 测试发布必须等待所有硬件完成。

## 业务设计约束

- 保留旧协议的明确兼容路径；迁移后的语义需要审阅。
- 新版本的受约束随机顺序可能与旧算法不同；研究进行中不能仅凭相同 seed 跨版本混用。
- 自由布局不自动缩放刺激；尺寸变化可能改变实验含义。
- SDK/Hosted/协作配置不作为首次创建本地实验的必经步骤。
- 任意脚本注入、全功能统计分析、招募排程、云端实时协作和托管 SaaS 不是本轮改版承诺。

## 执行顺序

先完成样板流程的业务和页面设计，实施编辑器及准备页面的统一体验，再扩大到数据管理。每项修改同时核对操作路径与数据输出。功能验收遵循[发布检查](RELEASE_CHECKLIST.md)，真人任务遵循[可用性规程](USABILITY_STUDY_PROTOCOL.md)。

旧 W1–W5 与累计优化记录已从当前计划移除；需要追溯时见 [beta.4 历史计划](https://github.com/kyzzz22/physioflow-app/blob/68a3451c3f33dcb8cbf87f53d612bf0938e990d1/docs/refactor/OPTIMIZATION_PLAN.md)。
