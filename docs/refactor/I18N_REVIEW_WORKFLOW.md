# 多语言审查工作流

`npm run audit:i18n` 会扫描 `src` 下的 JavaScript/JSX 文件，并生成 [I18N_AUDIT.md](./I18N_AUDIT.md)。

审查时按文件和类型处理：

1. 先处理 `JSX text` 和按钮、输入框的 `placeholder/title/aria-label`。这些通常是系统界面文案，应该迁移到 `useT()`。
2. 再处理 `string/attribute` 中的错误提示、弹窗和状态文案，补充中文和日文词条。
3. 跳过实验作者输入的题目、指导语、媒体来源、变量名、数据字段和文件名；这些属于实验内容或数据，不属于界面语言。
4. 每次新增词条后重新运行脚本，并在浏览器中切换 `EN → 中文 → 日本語`，检查占位符、数量插值和长文本布局。

脚本采用启发式过滤，因此报告中的 missing 数量不是需要全部翻译的数量，也不能证明全部界面文本已覆盖。它提供初步候选清单；模板字符串、动态组合文案、解析失败文件以及各语言实际翻译质量仍需人工补充检查。

建议将确认后的界面词条逐步改成命名空间键，例如 `canvas.freeEdit`、`checks.missingMedia`，不要继续增加由完整英文句子作为 key 的词条。迁移完成前保留现有 DOM 翻译层作为兼容机制。
