## 少人数で操作を確認する場合

[研究者・実験員・参加者の手順](../../USER_TRIAL_JA_2026-10-14.md)を使用します。ブラウザーと版、画面サイズ、日付、観察者コード、役割、実行IDを記録してください。各手順について自力で完了したか、時間、必要だった説明、期待と実際の結果を残します。自動テストや未実施の欄を成功として記入しません。

追加で確認する操作は以下です。

1. テンプレート設定を変更して作成し、保存・再表示で値が維持されるか確認します。キーボードや短い画面で迷った操作を記録します。
2. ランダム分岐の重みを空欄と0に設定し、意味の違いと全零エラーを理解できるか確認します。
3. 条件・ループで数字比較の空欄を修正し、どの設定が問題か分かるか確認します。
4. 実験員画面で実験待ち、切断、確認待ちを区別できるか確認します。理由を記入して操作した後、実験画面と記録を照合します。
5. 不正な比較値で実行が止まる場合、案内から入力や前の回答を確認する行動が分かるか記録します。

これらは最近の改修の観察項目です。正式評価の課題1–5を置き換えません。疑似信号や確認用素材は明記し、実機・原刺激の結果として扱いません。DB操作にはServerの実行環境が必要です。

## 正式な可用性評価の場合

[規程](../../refactor/USABILITY_STUDY_PROTOCOL.md)の参加者群、五つの課題、指標と三者署名を維持します。[空の結果JSON](study-results.empty.json)を別名でコピーして、実際の観察を記入してください。未実施の署名はfalseのままです。観察のフィールド仕様は元の規程に従います。

リポジトリのルートで実際の結果を検証します。

```bash
npm run verify:usability-study -- docs/trials/beta.18/study-results.actual.json
```

空のテンプレートは人数0・観察0・署名なしとして不合格になります。準備完了と試用合格は別です。少人数の操作確認で正式評価の合格を宣言しません。

実行ID、再現手順、期待結果、実際結果、重大度、修正・再確認を不具合に添付します。記録には本名、アクセスキーやDBトークンを含めません。
