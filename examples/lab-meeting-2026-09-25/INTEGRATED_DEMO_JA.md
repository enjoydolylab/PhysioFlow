# PhysioFlow × BrainFlow｜会議要件をつなぐ実演

**発表の主線：実験 ID → 参加者 ID → プロトコル → 映像・回答 → EEG プレビュー → marker → 原始記録と会話記録の照合。**
実演目安は 10〜15 分。Synthetic Board を使用する場合は合成信号であることを最初に伝えます。

## 起動

1. 配布 ZIP を展開し、`START_BRAINFLOW_MAC.command` または `START_BRAINFLOW_WINDOWS.bat` を実行します。Python 3 が必要です。初回だけ BrainFlow 依存関係をインストールするためネット接続が必要です。発表前に一度起動してください。
2. これひとつで Web アプリ（8016）と BrainFlow 代理（8765）が起動します。旧 `APP/start.py` と同時に起動しないでください。別のサービスを勝手に停止せず、先に自分の旧デモを終了してください。
3. 起動時に、実際の Board メタデータを使った `CONNECTED/` 内の 5 プロトコルを生成します。主実験は `CONNECTED/01_READY_TO_RUN.protocol.json`。ホームで読み込み、参加者 ID `QA-DEMO-001` を入力してテスト実行します。
4. 実行準備画面で、起動したターミナルの `token` を貼り付けます。接続後、⌘⇧O / Ctrl+Shift+O で操作バーを表示すると 4 チャンネルの値が見えます。token はスライド・画面共有に出さないでください。
5. 終了時はまずアプリの保存完了を確認して出力し、ターミナルで Ctrl+C。ブラウザを閉じても原始記録は止まりません。

ソースからの起動：`tools/brainflow/.venv/bin/python scripts/launch-integrated-demo.py`。あらかじめ `npm run build` と BrainFlow のインストールが必要です。

## 10〜15 分の発表台本

| 順番 | 実際に操作すること | 説明 |
| --- | --- | --- |
| 1 | 画布、BioDB 設定、参加者 ID を見せる | 実験 ID はプロトコルで保持。参加者 ID と session ID、采集 runId を関連付ける。ローカルの意味 ID は研究室 DB の UUID と同一とは限らない。 |
| 2 | BrainFlow 接続、主試バーを開く | 実際の BrainFlow ライブラリで採集。Synthetic は本物の脳波ではない。ブラウザはプレビュー、全サンプルは採集側に残る。 |
| 3 | 4 動画、SAM、Likert | 前後半に slow / pulse を各 1 本。重複なし。映像終了で次へ進み、回答とイベントを保存する。素材には QA 表示。 |
| 4 | A：外側 2 × 内側 2 とランダム分岐 | グループ単位の順序は変えても内部の流れを保つ。B と順序が入れ替わる。 |
| 5 | B：1 問目「デモ」、2 問目へ、保存確認後にページ再読み込み | ホームの「実験を再開」から token を再入力。入力値、問題位置、実行計画を復元。採集プロセスの runId は同じまま、原始記録が継続。 |
| 6 | B の自信度を 2 にする | 条件付き補足質問が現れる。値を 3 以上に戻すと不要な回答は提出対象から外れる。 |
| 7 | 完了・保存・出力 | セッション ZIP と `brainflow-recordings/<runId>/` を対応付ける。protocol の条件、回答、実行順、イベント marker の記録を確認する。 |
| 8 | セッション管理 → PhysioDB 原始記録のローカル確認 | 研究室ネットワークなしでも JSONL と行番号・単位の確認はできる。実 DB への認証・書き込み・読戻しは環境が整ってから行う。 |

A/B の実演順はセッションごとに変わります。最初の 4 動画の後は `README_JA.md` と同じ流れです。

## 会議の「5 パターン」

すべて `CONNECTED/` 版には BrainFlow 接続と異なる実験 ID が付きます。同じ参加者 ID を使っても session ID が異なり、原始ログの session_attached で対応を確認できます。前の実験を保存・終了してから次を始めます。

| ファイル | 目的 | 目安 |
| --- | --- | --- |
| 01_READY_TO_RUN | 主実験：映像・SAM・行列・平衡ランダム・グループ・復元 | 5〜8 分＋説明 |
| 02_NESTED | 入れ子ループとランダム分岐を短く確認 | 約 1 分 |
| 03_RECOVERY | 質問票の草稿復元と条件追問を短く確認 | 約 1〜2 分 |
| 04_STROOP | 8 試行、色へのキー反応、正誤・反応時間 | 約 30 秒 |
| 05_GONOGO | 10 試行、X に Space、O には反応しない | 約 30 秒 |

## 上流機能の補足展示

主実験を複製してから同種ノードを複数選択し、質問や待機時間を一括編集して元に戻します。素材登録は `02_MEDIA_BINDING.protocol.json` と `media/`、バージョン管理は保存・凍結・次の草稿、テストの前ページ操作は主試バーで実演します。正式実験ではテスト用の前ページ・退出ボタンは表示しません。正式実行の検証には書き込み可能な保存フォルダーが必要です。

## データを読むときの区別

- `session.json` とプロトコル・回答・イベント：PhysioFlow が保存する実験記録。
- `metadata.json`、`samples.jsonl`、`events.jsonl`：BrainFlow 代理の全チャネル原始記録と実験 ID / 参加者 / session の対応。
- marker_accepted は挿入要求の受付。原始サンプルの marker 行と照合して確認する。時計の偏差補正は未実装で、ミリ秒精度の実機同期を主張しない。
- 実機未接続、実 PhysioDB 未接続、40 本の原動画・約 112 分間の原時長は未検証。Synthetic と短いテスト動画の実演を、その検証の代わりにしない。
